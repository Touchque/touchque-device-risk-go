# Changelog

All notable changes to this project will be documented in this file. The
format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

Go modules are versioned via git tags (e.g. `v1.0.0`), not a manifest field;
the version below is the tag this module should be released under next.

## [1.1.0] — 2026-11-26

### Added
- **`BotCheck(ctx, BotCheckRequest)`: which bot sent one request your server received** (`POST /device-risk/bot-check`), for the visitors that never run your page's tag (ChatGPT-User, GPTBot, crawlers, curl, scripts). It sends the visitor's `IP`, `Headers` (in the order they arrived, or as a set with `HeaderOrderUnknown`; `[]` for a request that had none), `Method`, `URL` (host and path only), and `HTTPVersion` and `TLS` (`Ciphers`, `JA4`) only when you set them from what your edge saw. Returns `*BotCheckResult`: `Bot` (`Result`, `Category`, `Provider`, `Name`, `Identity` verified, unverified (a spoofed name) or claimed, `VerifiedBy`, `Confidence`, `Rule`, `Reasons`), `Network` (`ASN`, `ASNOrg`, `CountryCode`, `Hosting`; nil when Touchque cannot tell), `Suggestion` (allow, block, challenge: advice in shadow, never enforced), `RulesVersion` and `Raw` (fields this version does not know). Unknown values come through as they came; an answer it cannot read is `not_detected` and `allow`. `BotCheckRequestFrom(r *http.Request, clientIP)` builds the request from net/http (Host and Transfer-Encoding put back, HTTP/2 and 3 names in lower case; never `r.Proto`, the connection to your server). Authorization, Cookie, Proxy-Authorization, X-Api-Key and Set-Cookie go with empty values. What the visitor sent never makes it fail: the first 100 headers go, a name is cut to 128 and a value to 4096 characters, the body is kept under 32 KB and marked `truncated`; a header HTTP does not allow, an odd method or a URL Touchque could not read is left out. Only no IP is a `*ConfigError`, before anything is sent. `BotCheckBody`, `ParseBotCheck`, `BotResults`, `BotCategories`, `BotIdentities`, `BotVerifiedBy`, `BotConfidences`, `BotSuggestions`, `BotCheckHTTPVersions`, `BotCheckBlankedHeaders`.
- **Network kind** (absent from older servers; nil for an identification from before it): `CheckResult.Network`, and the `network` of `GetEvent` answers and `SearchEvents` rows, documents `kind` (`NetworkKinds`: `residential`, `mobile_carrier`, `education`, `business`, `public_wifi`, `hosting`, `proxy`, `vpn`, `tor`, `relay`, `unknown`; an open list, new values may be added in minor versions), `kindSource` (`address`, `network`, `mixed`, `network_open`, `name`), `vpn`, `shared`, `sharedVisitors24h` and `sharedAccounts24h` ("at least" counts: 1, 2, 5, 10, 100 or 1000) and `lookAlikeMatching`, plus the `proxy` flag and the `relay` type the comment lacked. The map comes through as the API sent it.
- `SearchOptions.NetworkKind` (sent as `networkKind`, as it is, so a newer kind works) and `SearchOptions.Shared` (`*bool`, sent as `shared=true` or `shared=false`). `NetworkKind` matches only identifications classified since network kind exists; `Shared` false matches only the ones counted and not shared (one that was not counted matches neither). Older servers ignore both.
- **AI agents on the page**: `CheckResult.Bot` documents the AI agents' tools `claude_agent` (the Claude app's browser or Claude in Chrome), `comet_agent` (Perplexity Comet), `genspark_agent`, `browser_use`, `stagehand` and `skyvern` (each `tool_<name>` in the reasons, like the automation tools), the reasons `cdp_input`, `input_no_focus`, `insert_text_bulk` and `scripted_click` (servers since 2026-11-25; absent from older servers), and `headless_window` and `emulator`, which the comment lacked. `Signal.Code` `device_ai_agent` also covers an agent's marks on the page. Values come through as strings, unknown ones included.
- `CheckResult.Visitor["mark"]`: the mark actually applied to the identification (`step_up` always, `trusted` only when the browser matched by its stored key or id, never by traits, else nil), in `Check` and `GetEvent`; `ParseCheck` reads any other value as nil (the answer's own map is not changed). `status` stays your admin's mark. Absent from older servers.

## [1.0.0] — 2026-11-24

### Added
- **Touchque Device Risk as its own module**, `github.com/Touchque/touchque-device-risk-go` (package `devicerisk`). Device risk leaves the main Go SDK (6.0.0 no longer has `Client.DeviceRisk`): `devicerisk.New(config ...*Config)` and `devicerisk.NewClient(*Config)` with their own small client (the same API key and secret, `TQ_API_KEY` / `TQ_API_SECRET` / `TQ_API_URL`, the same request signing, timeout and errors as the main SDK: `*APIError` with the `ErrFeature*` sentinels, `*NetworkError`, `*ConfigError`).
- `Check(ctx, CheckOptions)` (`POST /device-risk/check`), `GetEvent(ctx, requestID)` (`GET /device-risk/events/{requestId}`), `SearchEvents(ctx, SearchOptions)` (`GET /device-risk/events`) and `ParseCheck`, as they were on `Client.DeviceRisk` (the types lose their `DeviceRisk` prefix: `CheckOptions`, `CheckResult`, `Signal`, `SearchOptions`, `SearchResult`; `DeviceRiskEvents` / `DeviceRiskReports` are `CheckEvents` / `Reports`).
- **`Activity(ctx, ActivityOptions)`: report what a visitor did that your server saw** (`POST /device-risk/activity`): `Type` (`payment_attempt`, `login_failed`, `not_found`, `forbidden`, `otp_sent`, `code_failed`), `RequestID`, `VisitorID`, `ClientIP`, `ExternalUsername`, `Outcome` (`approved`, `declined`, `error`), `Card` (`*Card{BIN, Last4}`), `Phone`, `Path`. Returns `*ActivityResult` (`Recorded`, `VisitorID`, `PathClass`, `Signals`: `abuse_card_testing`, `abuse_card_shared`, `abuse_login_failures`, `abuse_probing`, `abuse_otp_pumping`, `abuse_code_guessing`). A `Card` that is not exactly a 6-8 digit BIN and 4 last digits (a card number) is a `*ConfigError` before anything is sent. `ActivityBody`, `ParseActivity`.
- `CheckResult.Suspect` (`*Suspect`: the suspect score in shadow, `Score` 0-100, `Band`, `WouldDo`, `Mode`, `Reasons` with `Code`, `Points`, `By`, `Text`) and `CheckResult.AccountDevice` (`*AccountDevice`: `Status` known, likely, new or first, `VisitorID`, `Since`); `ParseSuspect` and `ParseAccountDevice` read them from `GetEvent` answers and `SearchEvents` rows. `MatchedBy` lists `fpc` (the first-party cookie).
- `EventDeviceRiskSignal` and `EventDeviceRiskAlert` (were in the main SDK's webhook constants).
- `CheckResult.Bot` documents `type` (`ai_agent`, `automation`, `script` or nil), `tools`, `agent` and `input` on servers since 2026-11-24; `Signal.Code` lists `device_pointer_synthetic`, `device_new_storage_burst`, `device_network_signup_burst`, `device_input_synthetic` and `device_ai_agent`.
